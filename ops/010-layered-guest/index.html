01

Intel Brief

CONTEXT

MITRE ATT&CK T1622: adversaries check whether a debugger or tracer is watching, and change behavior when one is. This file builds a four-layer stack around that check, then takes the defender's side with a different observer per layer.

The stack idea in one sentence. Each layer defeats exactly one way of looking, and every new layer is a new surface a different way of looking can see.

Why it matters. A tracer (strace) is how an analyst watches a program's system calls. A payload that can tell it is being watched can save its real behavior for when nobody is looking. The check here is cheap and direct: every Linux process has a status file at /proc/self/status, and its TracerPid field names the tracing process, or 0 when none is. One file read, no privilege, and the payload knows what the analyst hoped it could not: whether anyone is watching.

Why not just look harder. Staring longer at the process list cannot beat a borrowed name, because the borrowed name was built for exactly that stare. The fix is never a harder look through the same observer. It is a different observer.

LayerDefeats this observerFalls to this observer
1. Tracer gate: the payload reads its own TracerPid and exits silently if nonzeroThe analyst's tracer (strace)None: it dies. The death is the tell.
2. Hidden directory: the payload lives in .sys-cacheThe default listing (ls)ls -a, find
3. Borrowed name: argv[0] set to syslog-helper at launchThe process-table glance (pgrep)/proc/PID/cmdline, /proc/PID/exe
4. Sleeper: the payload sleeps 900 seconds after runningNothing; it buys inspection timepkill, once found

Terms, earned where they first appear. A tracer attaches with the ptrace system call; the kernel records its process id in the tracee's TracerPid field. /proc/self is the current process's own /proc entry, so /proc/self/status is the payload reading its own record. The read must happen in the payload itself: a child process would report the child's own TracerPid, which is why the script uses a shell loop instead of delegating to awk or grep. argv[0] is the process's self-reported name, set by whatever launched it; exec -a overrides it. The kernel keeps two facts that do not consult that story: /proc/PID/cmdline, the full command line including the real script path, and /proc/PID/exe, a link to the actual executable file. A dot-directory is a name starting with a period, hidden from plain ls by a display convention from the 1970s, not by any filesystem enforcement.

The concrete case. /tmp/gh010 holds one visible file, notes.txt, and one hidden directory, .sys-cache, holding sync.sh. Under strace the payload reads a nonzero TracerPid and exits before touching its marker file. Launched clean under a borrowed name, it runs, touches .marker, and sleeps. Plain ls prints one name. pgrep prints a boring one. /proc prints the truth.

Scope. T1622 Debugger Evasion covers every way a program detects analysis: TracerPid checks, timing checks, breakpoint scans. This file works the TracerPid case end to end on Linux, then stacks it with T1564.001 (the hidden directory) and T1036 (the borrowed name) to show how layers compose: each new layer defeats one observer and exposes a new surface.

02

Target Environment

LOADOUT

Ubuntu 24.04.5 LTS, bash 5.2, x86-64, strace. No privilege, no network, no persistence. The lab is one directory (/tmp/gh010), one decoy file (notes.txt), one hidden directory (.sys-cache), one payload script (sync.sh).

1

Build the lab

One directory, one decoy, one hidden directory. notes.txt is the boring visible file the casual listing sees.

bash
$ rm -rf /tmp/gh010; mkdir -p /tmp/gh010/.sys-cache && cd /tmp/gh010 && touch notes.txt && ls
notes.txt

Fresh lab, decoy inside, shell moved into it. Now the payload, written into the hidden directory. The quoted 'EOF' keeps the shell from expanding anything in the heredoc.

bash
$ cat > .sys-cache/sync.sh <<'EOF'
> #!/bin/sh
> # GH-010 lab payload. Benign: reads TracerPid, touches one
> # marker, then sleeps. No network, no persistence, no privilege.
> # Layer 1 (T1622): the payload reads its own TracerPid.
> # Tracer attached? Exit silently. No tracer? Run.
> tpid=0
> while read -r key val _; do
>   if [ "$key" = "TracerPid:" ]; then tpid=$val; break; fi
> done < /proc/self/status
> if [ "$tpid" != "0" ]; then
>   exit 0
> fi
> cd "$(dirname "$0")" || exit 1
> touch .marker
> sleep 900
> EOF
2

The payload: sync.sh

Fifteen lines. The tracer gate lives or dies in this file, so every line is glossed.

sh: /tmp/gh010/.sys-cache/sync.sh
#!/bin/sh
# GH-010 lab payload. Benign: reads TracerPid, touches one
# marker, then sleeps. No network, no persistence, no privilege.
# Layer 1 (T1622): the payload reads its own TracerPid.
# Tracer attached? Exit silently. No tracer? Run.
tpid=0
while read -r key val _; do
  if [ "$key" = "TracerPid:" ]; then tpid=$val; break; fi
done < /proc/self/status
if [ "$tpid" != "0" ]; then
  exit 0
fi
cd "$(dirname "$0")" || exit 1
touch .marker
sleep 900

tpid=0 assumes unwatched until proven otherwise. The while loop reads /proc/self/status line by line in the shell itself, no child process, so /proc/self is the payload (delegating to awk or grep would read the child's own status). On the TracerPid: line the value is saved and the loop stops. Nonzero means a tracer is attached, and exit 0 dies silently: an error message would itself be evidence. cd "$(dirname "$0")" moves into the script's own directory so the marker lands beside the payload wherever it was launched from. touch .marker is the only write the script ever makes, and the proof it executed. sleep 900 keeps the process alive fifteen minutes so the defender has something to find.

03

Phase Red: the attack succeeds

ATTACK

Watch the attack succeed first. Then watch it disappear three ways.

1

Launch the attack

One command launches the payload in the background, wearing a false name.

bash
$ exec -a syslog-helper bash ./.sys-cache/sync.sh &
[1] 10999

exec -a sets argv[0], the process's self-reported name, to syslog-helper before launching. A real bash binary runs the script, so the borrowed name survives (a shebang launch would re-execute the interpreter and drop it). The [1] line is the shell confirming the background job and its process id.

2

The attack worked

One check proves the payload executed. The marker file is the proof: only a running payload creates it.

bash
$ sleep 1; test -e .sys-cache/.marker && echo "payload ran: marker created"
payload ran: marker created

That line is the whole attack succeeding. No tracer was attached, TracerPid read 0, the gate passed, the payload touched its marker and went to sleep. Everything after this is the attacker making that success hard to see.

3

Invisible in the file listing

Same directory, two questions.

bash
$ ls; echo ---; ls -a
notes.txt
---
.  ..  .sys-cache  notes.txt

ls shows the decoy. ls -a shows the hidden directory. Nothing changed between the commands except the question asked. Layer two defeats the default listing and nothing else.

4

Invisible in the process table

Ask the process table who is running.

bash
$ pgrep -af syslog-helper
10999 syslog-helper ./.sys-cache/sync.sh

One process, wearing a boring name. pgrep matched the borrowed argv[0] against the pattern. The process table repeats the name; it never checks whether it is true. Layer three defeats the casual glance and nothing else.

5

Invisible to your debugger

Now try to watch it. The payload is copied aside and run under strace, the standard way to observe a program's system calls.

bash
$ mkdir -p /tmp/t; cp .sys-cache/sync.sh /tmp/t/; chmod +x /tmp/t/sync.sh; strace -f -o /dev/null /tmp/t/sync.sh; echo "rc=$?"
rc=0

rc=0. That is a quiet death, not a crash. strace attached, the payload read a nonzero TracerPid, and it exited before its first write. The copy keeps the live lab untouched.

bash
$ test ! -e /tmp/t/.marker && echo "no marker: it saw the tracer and played dead"; rm -rf /tmp/t
no marker: it saw the tracer and played dead

No marker: the gate held. The payload never ran, so there is nothing to analyze. Layer one defeats the tracer and nothing else. Three layers, three observers defeated, and the attack from step 2 is still sleeping where you cannot see it.

Stealth confirmed

The attack ran and proved it with a marker. The default listing shows one decoy file, the process table shows a boring name, and a tracer sees the payload die before it does anything. The hiding cost one leading dot, one borrowed name, one /proc read.

04

Phase Blue: change the observer

DEFENSE

Detection is changing the observer, not looking harder. Then removal.

1

What the victim sees

Triage that stops at the default listing closes the case here.

bash
$ cd /tmp/gh010 && ls
notes.txt

One boring text file. The payload keeps sleeping.

2

Ask differently

First observer change: ask ls to skip its dotfile courtesy.

bash
$ ls -a
.  ..  .sys-cache  notes.txt

There is the hidden directory. Same observer, different question, and layer two is gone.

3

A boring name

The process table, as the attacker wants you to read it.

bash
$ pgrep -af syslog-helper
10999 syslog-helper ./.sys-cache/sync.sh

One sleeper with an unremarkable name. Nothing here says attack. So change the observer again.

4

The kernel's two honest answers

argv[0] is a story the process tells. These two are facts the kernel keeps.

bash
$ P=$(pgrep -f '[s]yslog-helper'); echo "pid=$P"
pid=10999

That pid goes into two kernel files that never consult argv[0].

bash
$ tr '\0' ' ' < /proc/$P/cmdline; echo; readlink /proc/$P/exe
syslog-helper ./.sys-cache/sync.sh
/usr/bin/bash

/proc/PID/cmdline is the full command line: the borrowed name first, then the real script path it was launched with. /proc/PID/exe is a link to the actual executable file, /usr/bin/bash, which no argv[0] can rewrite. Two kernel facts against one self-reported name: that is what changing the observer buys. Layer three is gone.

5

Proof it ran here

find walks the tree at the filesystem level, where a leading dot is just another character. The dotfile courtesy does not exist down here.

bash
$ find /tmp/gh010 -name '.*' | sort
/tmp/gh010/.sys-cache
/tmp/gh010/.sys-cache/.marker

Two hidden paths, by their real names, marker included. The marker is the proof the payload executed in this directory. -name '.*' matches names starting with a dot; the quotes keep the shell from expanding the pattern first; sort orders the output.

6

The evasion is the evidence

The tracer gate was the attacker's defense. Turned around, it is a confession. Attach strace and watch what happens.

bash
$ rm -f /tmp/gh010/.sys-cache/.marker && chmod +x /tmp/gh010/.sys-cache/sync.sh; strace -f -o /dev/null /tmp/gh010/.sys-cache/sync.sh; echo "rc=$?"
rc=0

rc=0, same quiet death as the red phase. The marker was removed first, so check whether the payload ran.

bash
$ test ! -e /tmp/gh010/.sys-cache/.marker && echo "no marker: it saw the tracer"
no marker: it saw the tracer

No marker. A process that dies the moment a tracer attaches is telling you it checks for tracers, and that confession costs the defender nothing: no payload execution, no risk. This is the T1622 tell. Layer one is gone.

7

Kill it, remove it

Detection done. Stop the process, then remove the files.

bash
$ pkill -f '[s]yslog-helper'; sleep 0.5; pgrep -af syslog-helper || echo "process gone"
process gone

pkill signals by name pattern. The [s] bracket keeps pkill from matching its own command line and killing the shell that runs it. "process gone" is the confirmation: no matching processes remain.

Before the files go, scope the incident: persistence, timeline, ownership. The layered guest earned its name by stacking evasions; assume the visible layer is not the only one until the persistence sweep and the timeline say so.

bash
$ stat -c '%y %U %n' /tmp/gh010/.sys-cache/*     # when it arrived, who owns it
$ crontab -l 2>/dev/null; systemctl --user list-units --all 2>/dev/null | grep -i -E 'sync|cache|syslog'
$ grep -rl 'sys-cache\|syslog-helper' ~/.bashrc ~/.profile /etc/cron* /etc/systemd/system 2>/dev/null
bash
$ rm -rf /tmp/gh010; ls /tmp/gh010 2>/dev/null || echo "lab directory gone"
lab directory gone

rm -rf removes the whole tree, hidden names included: rm never asked the display either. The error is the confirmation. No process, no files, no marker. Nothing persists.

Detection verified

Every layer fell to a different observer, the tracer gate confessed without the payload ever running, and the lab directory is gone.

05

Countermeasures

DEFENSE

Three moves, in order: change the observer, watch the writes, decide what may run. Each is one way, not the way.

1

Mitigate: compare observers, do not browse

Stop asking any single tool and start cross-examining them. Compare cmdline against exe, minus the known-benign classes: a login shell reads argv[0]="-bash" against exe /bin/bash; a shebang script reads argv[0]="/path/script" against the interpreter in exe, the normal interpreter case; busybox applets and distro exec -a wrappers rename on purpose too. Without those exclusions, comparing cmdline against exe as a standing check pages the team for every login shell on the fleet. Compare the process table against the filesystem too: anything executing from a dot-directory earns a closer look.

bash
$ tr '\0' ' ' < /proc/$P/cmdline; echo; readlink /proc/$P/exe
syslog-helper ./.sys-cache/sync.sh
/usr/bin/bash

The standing-check form, narrowed so the benign classes stay quiet. This is the fleet form of the blue phase: the idea does not change, only the coverage.

bash
$ for d in /proc/[0-9]*/; do
  pid=${d#/proc/}; pid=${pid%/}
  a0=$(tr '\0' '\n' < "$d/cmdline" 2>/dev/null | head -1); [ -n "$a0" ] || continue
  exe=$(readlink "$d/exe" 2>/dev/null); [ -n "$exe" ] || continue
  base=${exe##*/}
  case "$a0" in
    "$base"|"$exe"|/*|-"$base") continue ;;  # real name, full path, script path, login shell
  esac
  echo "pid=$pid argv0=[$a0] exe=[$exe]"
done
pid=5 argv0=[syslog-helper] exe=[/usr/bin/bash]

Tested: in the lab this flagged only the syslog-helper process against /usr/bin/bash. The tracer tell gets the same treatment in reverse: you cannot strace every process, so sample a suspicious one under strace in a sandbox and watch for the quiet death, exactly the blue phase's step 6, labeled as sampling rather than monitoring.

Honest limit. Comparison only works when both answers are trustworthy. A rootkit underneath (T1014) hides from /proc and the process table alike: no observer comparison helps when every view is mediated.

2

Monitor: watch writes, not names

A hidden file is still a created file, and a borrowed name still belongs to a real exec. File integrity monitoring (D3-FIM) notices the marker appearing in a watched directory regardless of its first character. Software inventory (D3-SWI) flags binaries that were never supposed to be on the machine, whatever their names start with. Creation-time telemetry records the image path and the argv array as separate fields of the same execve event. The theater is not hidden from the log; it is in it, as a0. Detection is the join: image path says what ran, a0 says what it claimed to be.

bash
$ auditctl -a exit,always -F arch=b64 -S execve -k exec-all
$ auditctl -a exit,always -F arch=b32 -S execve -k exec-all
$ ausearch -k exec-all --start recent -m EXECVE,SYSCALL 2>/dev/null | grep -B2 'a0='

Read each hit as a pair: type=SYSCALL ... exe="/real/image" plus type=EXECVE ... a0="claimed-name". Good versus bad: good is exe="/usr/bin/bash" a0="-bash" (a login shell), exe="/usr/bin/python3" a0="/opt/app/main.py" (a shebang script), or a busybox applet. Bad is exe="/usr/bin/bash" a0="syslog-helper", or any a0 with no path relationship to exe and no benign explanation. Sysmon for Linux users get the same pair as Event 1 fields Image and CommandLine.

Honest limit. FIM sees the write only if it was already watching that path. Nobody watches all of /tmp by default. And the join trusts the log: a rootkit under /proc (T1014) defeats every observer comparison.

3

Prevent: decide what may run

Hiding is free, so prevention targets execution instead. Executable allowlisting means an unknown script dropped into a hidden directory never runs, whatever its name. Nothing here persists unless something runs it, so the inventory that matters is the process table, taken regularly, not the directory listing.

Honest limit. The tracer gate itself is not preventable by policy: any process may read its own status. And an allowlist is only as good as its list. TracerPid can also be masked by a careful tracer, so the gate is a tripwire, not a guarantee.

Countermeasures verified

Observers are cross-examined instead of trusted, writes are watched at the kernel's layer, execution is decided by policy, and every control's bypass is stated above.

06

Debrief

TAKEAWAY

Stealth is a stack: every layer defeats one observer and exposes a new surface, so the defender wins by changing observers, not by looking harder through the same one.

IOC checklist: signs this technique was used

  • A process that exits the moment a tracer attaches: tracer-aware behavior is itself the indicator
  • A process whose argv[0] disagrees with its /proc/PID/exe
  • A process executing from a dot-directory under /tmp, /var/tmp, or a service directory
  • Dot-directories appearing outside the usual home-directory clutter

Reproducibility checklist

  • Verified on Ubuntu 24.04.5 LTS, bash 5.2, strace, x86-64, on 2026-09-17
  • Both recordings are real executions on that platform, not simulations
  • No privilege needed; no network activity; no persistence mechanisms
  • Cleanup: pkill -f '[s]yslog-helper'; rm -rf /tmp/gh010 (both already run in the blue pass)
