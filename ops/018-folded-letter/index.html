01

Intel Brief

CONTEXT

MITRE ATT&CK T1140: adversaries decode or deobfuscate files or information at the moment of use, so the artifact at rest is armor, not content. This file folds a benign payload twice and runs it by decoding straight into a shell, so static inspection sees only opaque text. Then the defense: entropy triage flags the armor, a sandboxed safe-decode reveals the payload, the running decoded process is contained with evidence-first discipline, and a scheduled decode-hunt makes the control durable. Two actors: the attacker, who owns fold.py, note.folded, and unfold.sh; and the defender, who owns the entropy reads, the sandbox decode, the kill, and the scheduled hunt in the blue phase.

Why this technique. Every static control answers one question: what does this file contain. Hash blocklists, content signatures, grep, strings: all of them read the artifact at rest. Folding changes what is at rest. The bytes on disk are armor, layered transforms chosen so the original text never appears. The content exists in cleartext only inside the decode pipe, for a fraction of a second, between unfold.sh and sh. A scanner that reads the file sees the armor. The payload is never at rest in cleartext, so there is nothing at rest to match.

Why not ship it in cleartext. The obvious alternative is the naive dropper: a shell script on disk, executed directly. Break it on the concrete input: grep -l GHOSTLIGHT over the lab names /tmp/clear.sh instantly, strings would print its lines, any content rule keyed on the marker fires. The recording shows the measurement: grep -l finds the cleartext file and stays silent on note.folded. One artifact is found instantly; the other is invisible. That gap is what the folds buy.

Why not a single base64 layer. The next obvious alternative is one fold of base64, the classic decode-then-execute one-liner. Break it: base64 has a fixed 64-character alphabet, and defenders know it. A base64 blob is recognizable by its alphabet, and one base64 -d reverses it. The XOR fold breaks the alphabet: the middle layer is binary, not base64 text, so alphabet signatures do not match and a lone base64 -d of the middle layer yields garbage instead of the payload. The outer armor re-encodes to base64, so the stored artifact still looks like ordinary encoded text. Each fold defeats one cheap detector.

The mechanism, in one line. Obfuscation is transforming content to hide its meaning while keeping it recoverable. Encoding, here base64, is the binary-to-text armor that maps every 3 bytes to 4 text characters. A fold is one such transform applied in sequence. XOR with a key byte flips bits reversibly: applying the same XOR twice restores the original, so the decoder needs only the key, 0x5A here. Decode-then-execute is the pipeline that decodes standard input straight into an interpreter: ./unfold.sh note.folded | sh. The payload is cleartext only in the pipe between the two. Terms earned, no borrowing.

The concrete case, before the abstraction. In /tmp/gh018: fold.py reads payload.sh, 124 bytes, a benign stand-in that prints a marker and sleeps 600. base64 makes it text, XOR 0x5A breaks the alphabet, base64 armors it again: note.folded, 224 bytes. payload.sh is deleted; the delivered artifact is note.folded plus unfold.sh. unfold.sh reverses the folds, base64 -d, XOR 0x5A, base64 -d, to standard output. The attack is one pipeline: ./unfold.sh note.folded | sh. The marker prints, the sleeper starts, and the disk still holds only armor.

Scope. T1140 covers deobfuscation and decoding broadly: encoded payloads, encrypted blobs with embedded keys, packed binaries, runtime decoding. This file works the encoded-artifact case end to end: the two-fold packer, the decoder stub, the decode-into-shell execution, entropy triage, the sandboxed safe-decode, evidence-first containment, and the scheduled hunt. The payload is a benign stand-in that prints a marker and sleeps: it proves execution and touches nothing else. The lab runs in a disposable namespace because every blue-phase read targets the live decoded process.

fold.py
#!/usr/bin/env python3
"""fold.py (attacker's packer): payload.sh -> base64 -> XOR 0x5A -> base64 -> note.folded.

Two folds. The inner base64 armor hides the text. The XOR breaks the
base64 alphabet so signature scanners see no base64. The outer base64
armor makes the result look like ordinary encoded text.
"""
import base64

with open('/tmp/gh018/payload.sh', 'rb') as f:
    raw = f.read()
inner = base64.b64encode(raw)
xored = bytes(b ^ 0x5A for b in inner)
outer = base64.b64encode(xored)
with open('/tmp/gh018/note.folded', 'wb') as f:
    f.write(outer + b'\n')
print('folded %d -> %d bytes' % (len(raw), len(outer)))

fold.py, the packer, in full: read payload.sh as bytes; base64.b64encode makes it text, the inner armor; the generator expression XORs every byte with 0x5A, breaking the base64 alphabet so the middle layer is binary, not text; base64.b64encode again, the outer armor, so the stored artifact looks like ordinary encoded text; write note.folded with a trailing newline; print the size change. Two folds, each defeating one cheap detector.

unfold.sh
#!/bin/sh
# unfold.sh (attacker's decoder stub): reverses the two folds.
# Usage: ./unfold.sh note.folded
base64 -d "$1" | python3 -c "import sys;d=sys.stdin.buffer.read();sys.stdout.buffer.write(bytes(b^0x5A for b in d))" | base64 -d

unfold.sh, the decoder stub, in full: one pipeline that reverses the folds. base64 -d strips the outer armor; the python3 one-liner XORs every byte with 0x5A again, which restores the inner armor, because applying the same XOR twice is the identity; the final base64 -d strips the inner armor. Decoded bytes go to standard output, which is what the attack pipes into sh.

entropy.py
#!/usr/bin/env python3
"""entropy.py (defender's triage): Shannon entropy per file in a directory.

Armored or encoded blobs score near the top of their alphabet's range;
ordinary scripts and text score lower. A triage signal, not a verdict:
the verdict comes from safely decoding the flagged file.
"""
import math
import os
import sys
from collections import Counter


def entropy(path):
    with open(path, 'rb') as f:
        data = f.read()
    if not data:
        return 0.0, 0
    counts = Counter(data)
    n = len(data)
    return -sum(v / n * math.log2(v / n) for v in counts.values()), n


target = sys.argv[1] if len(sys.argv) > 1 else '.'
for root, _dirs, files in os.walk(target):
    for name in sorted(files):
        path = os.path.join(root, name)
        try:
            e, n = entropy(path)
        except OSError:
            continue
        flag = '  <-- OPAQUE' if e > 5.0 else ''
        print('%5.2f bits/byte  %6d bytes  %s%s' % (e, n, path, flag))

entropy.py, the defender’s triage, in full: walk the target directory; read each file as bytes; count byte frequencies; compute the Shannon entropy in bits per byte; flag anything above 5.0. Armored blobs score near the top of their alphabet’s range; ordinary scripts score lower. The flag is a triage signal, not a verdict: the verdict comes from safely decoding the flagged file.

decode-hunt.sh
#!/bin/sh
# decode-hunt.sh (defender's scheduled control): triage a directory for
# opaque files and attempt a SAFE decode of a COPY in a sandbox dir
# (D3FEND D3-FCDC: File Content Decompression Checking).
# It never executes what it finds. Run: ./decode-hunt.sh /srv/www
dir=${1:-/srv/www}
thresh=5.0
tmp=$(mktemp -d)
found=0
for f in "$dir"/*; do
    [ -f "$f" ] || continue
    e=$(python3 -c "import math,sys;from collections import Counter;d=open(sys.argv[1],'rb').read();c=Counter(d);n=len(d);print('%.2f'%(-sum(v/n*math.log2(v/n) for v in c.values())))" "$f")
    if [ "$(python3 -c "print(int(float('$e') > $thresh))")" = 1 ]; then
        found=1
        echo "OPAQUE: $f ($e bits/byte)"
        cp "$f" "$tmp/sample"
        if base64 -d "$tmp/sample" > "$tmp/dec" 2>/dev/null; then
            echo "  outer layer is base64; decoded first bytes:"
            head -c 48 "$tmp/dec" | od -A d -t x1 | head -3
        else
            echo "  not plain base64; escalate to the sandbox"
        fi
    fi
done
if [ "$found" = 0 ]; then
    echo "clean: no opaque files in $dir"
fi
rm -rf "$tmp"

decode-hunt.sh, the scheduled control, in full: for each file in the directory, compute its entropy with the same formula; above the 5.0 threshold, copy the file to a sandbox temp dir and try base64 -d on the copy; print the decoded first bytes, or escalate if it is not plain base64. It never executes what it finds. D3FEND D3-FCDC: File Content Decompression Checking names this shape: checking whether encoded sections decode.

Debrief

TAKEAWAY

When static inspection sees only armor, measure the file and decode a copy: the content is never at rest, so look at the moment of use.

IOC checklist: signs this technique was used

  • A file with high Shannon entropy (near the top of its alphabet’s range) that no human can read, especially newly arrived
  • Opaque text blobs: base64 blocks, hex dumps, long encoded strings in files that should be readable
  • Decode-then-interpreter pipelines in process trees or shell history: base64 -d piped into sh, xxd -r piped into sh
  • A payload marker that appears in logs but in no cleartext file on disk
  • Decoder tooling (base64, xxd, openssl enc, python3 one-liners) invoked with decode flags at odd hours or from odd parents

Reproducibility checklist

  • Verified on Ubuntu 24.04.5 LTS, x86-64, on 2026-09-23
  • Both recordings are real executions on that platform, not simulations
  • Runs as root in a disposable namespace (the lab folds its own payload; the assumed breach: something on the box delivered the folded artifact)
  • Cleanup: rm -rf /tmp/gh018 /tmp/sandbox; verify with ls /tmp
